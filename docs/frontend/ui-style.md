# 前端样式规范

面向 `forgepilot-web` 的编码约束。实现时同时遵守本文和根目录 `AGENTS.md` 中的「前端样式」一节。

## 原则

ForgePilot 工作台是企业后台，不是营销站，也不是云 IDE。视觉上保持安静、对齐、可读，让用户先看到状态和动作，而不是装饰。

- 只使用 Vue 3 和 Element Plus。不要引入另一套 UI 库，也不要为了视觉效果引入 Monaco、xterm 或重型图表。
- 颜色、间距、圆角和字体使用 `forgepilot-web/src/styles/base.css` 里的 `--fp-*` 变量。页面里不要再写一套互不相同的灰色和间距。
- 不要用内联 `style` 控制布局（例如 `style="width: 100%"`）。把布局写进 scoped CSS 或复用已有 class。
- 中文界面优先保证齐整：同一列数字、标签、输入框和按钮的左边缘必须对齐。

## 布局

- 登录、空状态和居中卡片使用全视口网格居中：`min-height: 100vh; display: grid; place-items: center;`，并给窄屏预留 padding。
- 登录后的壳层：左侧深色可伸缩侧栏（展开 `208px`，折叠 `64px`，状态写入 `localStorage`）+ 右侧顶栏与内容。顶栏高度 `52px`，保留平台名、通知、公告、用户与退出等公共入口。
- 内容区使用统一内边距（约 16–20px）。页面标题与筛选/动作放在同一行：左侧 `page-header__title` + `page-header__subtitle`，右侧 `page-header__actions`，避免大块空白。
- 同一页面里连续的卡片、表格、工具条之间用 `--fp-space-4`（16px），或给根节点加上 `page-stack`。
- 表单：登录等短表单使用 `label-position="top"`，避免「用户名」「密码」这种不同字数的标签把输入框挤歪。后台筛选和编辑表单如果标签在左侧，必须设置统一的 `label-width`。
- 表格列宽按内容含义设置：状态、项目名、时间用固定宽度，标题列自适应。空数据使用 Element Plus 的 `empty-text`，不要留下一块空白。
- 规约与文档页使用密铺三区：左侧文档列表、中间 Markdown 源码、右侧实时预览。

## 颜色与字体

- 页面背景 `#F3F5F8`，卡片和顶栏为白色，侧栏与编辑器底色 `#0F172A`，主文字 `#2F3540` / 墨色 `#1F2329`，次要文字 `#646A73`，边框 `#E5E6EB`，主色 `#2F6BFF`，浅主色 `#EAF1FF`，成功色 `#2BA471`。
- 控件高度约 `32px`，圆角 `6–8px`。通过覆盖 Element Plus 的 `--el-color-primary` 等变量保持一致。
- 字体栈：`"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`。不要把 `Segoe UI` 放在中文字体前面，以免中西文混排高低不齐。
- 日志、Diff 和 Markdown 源码使用等宽字体，深色底；增加和删除行分别用绿色和红色，与 `base.css` 中的 `.log`、`.diff`、`.diff-add`、`.diff-del` 保持一致。

## 组件用法

- 按钮：主操作 `type="primary"`，每个卡片或对话框里只放一个主按钮。次要操作用默认按钮，危险操作用 `type="danger"`。
- 反馈：请求失败用 `el-alert` 或页面内错误文案，文案要说明发生了什么，不要只写状态码。全页不要用浏览器原生 `alert`。
- 加载：列表和卡片用 `v-loading`，提交按钮用 `:loading`，两者不要同时无意义地闪烁。
- 不要覆盖 Element Plus 的盒模型到无法对齐的程度。需要微调时用 `:deep(...)` 只改当前组件，不要写全局 `el-*` 重置。

## 验收

改界面后至少检查：

1. 登录页在 1280×800 和手机宽度下卡片居中、输入框左右对齐、主按钮与输入框同宽。
2. 登录后侧栏可展开/折叠并记住状态；顶栏显示通知与公告入口；内容区没有错位或横向滚动（除非表格本身需要横向滚动）。
3. 中文标签、数字和西文混排时基线整齐，没有被错误字体栈撑歪。
4. 规约与文档页支持 Markdown 导入、在线编辑与实时预览，页面标题与工具条同一行。
